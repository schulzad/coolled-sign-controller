# Changelog

## Unreleased

- **Gallery:** every row now has a real panel recording (Nyan cat, Sonic, the Matrix still, and three new Gengar rows), cropped to the panel so it lines up with the 64×16 renders. The Gengar rows compare a plain 1-bit still (`--dither none`) with temporal stills at 16 and 79 subframes, whose renders are the blended previews: against the source the still is about 75 levels per channel off, 16 subframes about 5, and 79 about 1 — but the 79-subframe loop repeats only 12.7 times a second, and its recording shimmers. `gengar.jpg` is exempted from the `examples/downloaded/` ignore rule so its source can ship.
- **Previews now show what the panel lights.** A `--dither none` frame keeps its midtones until the codec cuts each channel at 127, and `--preview` saved it uncut, so a purple source previewed purple while the panel showed blue. Previews now apply the same cut (new `animation.render.threshold_to_panel`), and the Nyan cat, Sonic, and colour-bar `none` gallery renders were regenerated to match the panel.
- **Stills no longer inherit the scroll** native text leaves behind. The panel keeps its last movement mode across uploads and a still obeys it, so after `coolled text` a plain `coolled image` scrolled. `ProtocolRuntime.upload_frame_bundle` now follows every single-frame upload with `mode=1` (static) on the same session, which covers `coolled image`, `coolled text --no-scroll`, `coolled send`, and the API; the transfer summary prints `then mode=1 (static)`, and `still_mode=None` opts out. Animations, which have been recorded playing in place, get no mode step, and a codec without a mode command skips it. Confirmed on the panel 2026-10-30.
- A `--temporal` still's **`.png` preview is now the blend** of its subframes (their hold-weighted average, the tone the eye should see) instead of the first binarized subframe; a `.gif` preview still shows the raw subframes, which no GIF viewer plays fast enough to blend. New `animation.preview.blend_frames`.
- A temporal loop too slow to blend now **warns instead of passing silently**: past 16 subframes the 1 ms hold floor cannot keep the loop above the ~62 Hz fusion rate (79 subframes repeat at 12.7 Hz), so `coolled image` prints a `warning:` line and `/image` returns `warnings`, but the loop is still sent so the panel can be overdriven on purpose. The API's `temporal` cap rises from 32 to the 255-frame structural limit to match the CLI; the codec's frame budget still applies.
- Brought the specs up to date with the transport: `GuardedTransport.smdl` now covers the `progress` callback, `duration_ms`, bounded writes, the delay-paced fallback after 6 missed acks in a row, and fatal ack statuses, and no longer claims per-panel serialization or a transfer deadline that were never built. `PixelFramePipeline`, `SignControlService`, `DeviceProfileLedger`, and the manifest describe the warn-not-refuse rule, and `PixelFramePipeline` records the scan-line model and a per-pixel phase ramp that was rejected on hardware because it draws diagonal streaks.
- `coolled image`, `animation`, and `text` no longer print the full transfer plan/result JSON (every packet's bytes) by default; pass `-v`/`--verbose` to get it on stdout. The live progress line and the closing summary are the default output.
- Added a live **upload progress line**: `coolled image`, `animation`, and `text` redraw one stderr line while sending (`uploading 112/238 (47%), ~29 s left`), so a long `0x04` upload no longer looks hung. Time left comes from the panel's steady per-packet rate remembered from earlier uploads (`upload-rates.json` in the cache directory, learned from the second half of any upload of 60+ packets): every upload's first ~30 chunks are acked faster than the rest (153 ms, then about 220 ms, measured 2026-10-29), so averaging the upload so far undershot and then stalled. Replayed over a real 238-packet upload, the remembered rate cut the mean ETA error from 4.9 s to 0.5 s. It only draws on a terminal, so piped or logged stderr stays clean. The transport reports through a new optional `progress(sent, total)` callback on `send_packets`, threaded through `ProtocolRuntime.upload_frame_bundle` and `play_native_text`; a packet the panel rejects never counts as sent, and a dry run never reports. The closing transfer summary now prints the actual timing, `total=… transfer=… per_packet=…` (total includes finding and connecting to the panel; the per-packet rate only appears when every packet landed), and `TransferResult` records `duration_ms`. Also added feature-board card **F5** (pipelined chunk upload), which needs a hardware ack-window test before it can change the stop-and-wait default.
- Added **`coolled-verbs`**, a read-only MCP render surface (`opensign-verbs`, `[mcp]` extra) in the verbs-and-nouns shape of smdl-factory's `smdl-verbs`: `describe panel|legend` and `render text|pattern|image|animation|bundle`, which compiles through `PixelAnimationStudio` and returns each frame as text, one character per pixel, trimming scrolls and animations to the frame budget the CLI sends and taking the CLI's `fill` fit. It never encodes or sends. New `animation.preview.text_preview`.
- Corrected the stale **80-frame** animation budget across the README, roadmap, validation notes, and specs. The `0x04` payload limit is 30 KiB *including* its 27-byte header, so a 64x16 panel tops out at **79 frames**; 80 is rejected with `DATA_LENGTH_ERROR` (measured 2026-08-15 with decoded acks). The July "80 displays, 81 fails" reading predated correct ack decoding.
- Added a **feature board** spec (`specs/FeatureBoard.smdl`, registered in `specs/manifest.json`): design-only cards for a gap between scroll passes, a host-driven music-bars visualizer (opcode `0x01`, unverified), image/animation option parity, and compiling a multi-page program into a single `0x04` upload.
- Licensed the project under **MIT** (`LICENSE`). `THIRD_PARTY_NOTICES.md` carries the MIT notice for the chunking and bitplane helpers adapted from coolledx-driver, and `pyproject.toml` declares `license = "MIT"` (PEP 639) so the notices ship with the package.
- Added **side-scrolling animations**: a GIF/WebP/APNG can travel across the panel as a sprite (scaled to panel height, transparency preserved, own animation still playing) instead of playing in place. New `render_scroll_animation` + `alpha_key` in `animation.render`, `PixelAnimationStudio.create_scrolling_gif_bundle`, and `coolled animation --scroll [--scroll-px N] [--direction left|right]`. The scroll is faked host-side because native firmware scroll (opcode 0x02) can only march a single static bitmap; a full pass is thinned to the frame budget, so it obeys the ~79-frame / 30 KiB limit.
- Brought the HTTP API to **parity with the CLI**: `/animation` gains `scroll`/`scroll_px`/`direction` (side-scroll) plus `key_color`/`key_tolerance`, and `/text` now uses the device-native firmware scroll by default (`native=true`, with `speed`/`mode`), falling back to the host flipbook with `native=false`. Added `OpenSignRuntime.play_native_text`, extended `play_animation_base64`, capped the `/text` flipbook to the frame budget, and made the animation route tolerate a `data:` URI prefix.
- Made the toolkit usable **off a fresh clone**: the checked-in starter `device_profile.json` and the probe/profile defaults are now the codec-valid **64x16** (a multiple-of-8 height the bitplane codec accepts; corrects the stale 48x12 scaffold). The direct CLIs fall back to the starter when `device_profile.local.json` is absent, and `--preview`/`--dry-run` degrade gracefully (with a note) when a profile has no codec that can build a transfer plan, so a preview always renders.
- Wired per-chunk **ack decoding + NAK re-send** into `GuardedTransport`: the CoolLEDX codec now supplies an ack decoder (`decode_coolledx_ack`; status `0x00` success / `0x06` checksum error), `send_packets` is per-packet and re-sends a NAKed packet up to `nak_retry_limit`, and `TransferResult` gains `naks` / `nak_retries`. Backward compatible: with no decoder any notification still counts as an ack. The `0x06` path is not yet exercised on hardware.
- Brought the HTTP API up to the SignControlService spec: `/animation` now compiles a bounded base64 GIF/APNG server-side (subsampled to the device frame buffer), `/image` accepts `temporal` (FRC loop) plus `dither`/levels, and a dedicated `/bundle` route (with `/scene` alias) plays a pre-rendered frame bundle. Added `OpenSignRuntime.play_animation_base64` and extended `play_image_base64`.
- Refreshed the docs (`README`, `protocol.md`, `docs/module-map.md`, `VALIDATION.md`, `ROADMAP.md`) to match the implemented behaviour and the verified reference panel (64x16).
- Flipped the send activation trigger: the `coolled` and `opensign-send` CLIs and `scripts/flicker_probe.py` now write to the panel by default and take `--dry-run` to build a plan without BLE writes (replaces the old opt-in `--execute`). The `opensign-api` server is unchanged and stays render-only until started with `--execute`.
- Transmitting via `ProtocolRuntime` no longer requires a `verified` profile; `experimental` profiles may be written live (a controlled live test is how evidence is promoted), matching the `live_*` scripts.
- Added `scripts/native_scroll_experiment.py` to test the device's native text scroll (wide bitmap under the TEXT opcode + MODE/SPEED) instead of a rasterized flipbook.
- Extended `native_scroll_experiment.py` with `--speed-sweep` / `--speeds` / `--reassert-mode` to hunt 0x07 scroll-rate semantics by eye.
- Verified native-scroll SPEED (`0x07`): higher byte = faster; 255 is fast but readable (2026-07-14 speed sweep). Promoted `protocol.commands.speed` and `mode` to verified in the local profile. Opposite polarity from animation `coolledx_speed` (ms/frame).
- `coolled text` now uses native firmware scroll by default with `--speed 0..10` (maps to device byte 0..255). Added codec `encode_text_banner`, `ProtocolRuntime.play_native_text`, and `--flipbook` / `--no-scroll` escape hatches.
